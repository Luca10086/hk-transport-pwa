## 0. 摘要

| 面向 | 結論 |
|---|---|
| 架構 | **良好**：5 分頁 + NavigationView 三型態、CommandBar、Page refresh／Drill 轉場、獨立待機 Activity、資料層有真實單元測試（66 個全綠） |
| 資料層 | **紮實**：`K75PModel.gpsPos` 的視窗錨定設計正確、ETA 解析防禦性強且有測試、IO 失敗逐層隔離 |
| 待機／鬧鐘 | **4.4.1 前有兩個 critical 缺陷**（時鐘不走、離開後音訊永久失效）→ 已於 4.4.2 修復 |
| 功能對等 | **不齊全**：核心查詢能力（巴士站、通宵線、簡繁、港鐵線名、收藏管理）相對出貨版 WebView 有明確退步 |
| 最大風險 | 鬧鐘在重開機／改時區後不再排程；到站提醒因取樣週期與門檻不匹配而幾乎不會觸發 |

## 1. 已修復（4.4.2，含兩項當日回歸）

| # | 問題 | 嚴重度 | 修法 |
|---|---|---|---|
| 1 | 床頭時鐘不會走：重寫 W10M 版時漏掉即時時間狀態，`hhmm()` 只在 composition 時讀一次 → 畫面凍結在進入時刻，日曆亦不跨日 | critical | `StandbyScreen` 加每秒心跳 `tick`；`AlarmFace` 以 `remember(tick){ hhmm() }` 取值；`CalendarFace` 以 `remember(tick/30)` 重取日期 |
| 2 | 離開待機畫面一次後，內建合成音與**鬧鐘響鈴**永久無聲：`pump()` 以 `thread.isAlive` 為迴圈條件（恆真）→ 永不結束、`finally` 不執行、AudioTrack 洩漏；`releaseAll()` 後 `play()` 因執行緒仍活著而不重建 | critical | 改用顯式 `running` 旗標；`releaseAll()` 令執行緒結束並釋放；`play()` 視情況重建執行緒或 `trackRef.play()` |
| 3 | `CrashLog` 使用 API 28+ 的 `PackageInfo.longVersionCode`，而 `minSdk = 26` → Android 8.0/8.1 寫日誌時拋 `NoSuchMethodError`，日誌永遠寫不出來（正是用來診斷真機閃退的路徑） | high | 依 `Build.VERSION.SDK_INT` 分支取值 |

## 2. 待修問題（依嚴重度）

### P0 — 功能實質失效

| 問題 | 證據 | 影響 |
|---|---|---|
| **鬧鐘重開機／改時區後不重排** | `AndroidManifest.xml` 只宣告 `.data.AlarmReceiver`；無 `BOOT_COMPLETED`／`TIMEZONE_CHANGED`／`TIME_SET`／`MY_PACKAGE_REPLACED`；`AlarmRepo.schedule` 僅 3 個呼叫點（設定開關、選時間、隔日重排），App 啟動路徑無 | 重開機後鬧鐘靜默失效，但 UI 仍顯示「每天」 |
| **到站提醒幾乎不會觸發** | `work/RefreshWorker.kt` 為 30 分鐘週期取樣，而可設門檻為 3/5/10 分鐘；且 `catch (Exception) → Result.retry()` 會吞掉 `CancellationException` | 功能形同裝飾 |
| **收藏「巴士站」是死路** | `FavMapper` 對 `Kind.BUSSTOP` 硬寫 `route = ""`；`SearchRepo.favEta` 依 route 過濾 → 永不匹配；`displayName()` 回傳空字串 → 標題空白；詳情頁 `route.isNullOrBlank() → return` → 「無法載入站點」 | 使用者搜尋到的巴士站加星即壞 |
| **安全模式／減少動畫空轉** | `CrashGuard.isSafeMode` 只被讀作 CommandBar 標籤；`Settings.fx` 只被自身開關讀寫；無任何渲染路徑分支 | 崩潰時宣稱的自動降級從未發生 |

### P1 — 高風險

- 主執行緒解析多 MB JSON（KMB `/stop/` 實測 1.18 MB）；`chunked(6)` 節流因 `async` 立即啟動而失效
- `AlarmReceiver` 在主執行緒 `runBlocking` 讀 DataStore（Doze 喚醒後最慢，且與啟動 UI 共用 10 秒預算）
- 響鈴無震動（`VIBRATE` 已宣告但無 `Vibrator` 呼叫）、無 full-screen intent 備援、無前景服務
- 未檢查 `canScheduleExactAlarms()`；宣告了 Play 政策受限的 `USE_EXACT_ALARM`
- 音樂每秒重拉整包 metadata（含專輯封面 Bitmap）並每幀 `asImageBitmap()`
- 輕鐵分組漏 10 站、重複 1 站（魔術區間 `1..300 / 425..560 / 560..920`）
- `alarmOpen` latch：折起立放自動進入只生效一次，且返回鍵被無聲吞掉
- HKO 快取會用半空資料覆蓋良好預報；`updated` 解析成 `"00+08"`
- `DebugFlags.offline` 未被 `Http.postJson` 遵循

### P2 — W10M 合規與視覺

- 天氣與收藏仍使用彩色 emoji（`🌤️`、`🔔`／`🔕`）——與已修好的鬧鐘圖標同類問題
- 主外殼多處 `FontWeight.Light` 與規範的 Semibold 相衝（`Wp8PaneTitle`、`Wp8SectionTitle`、`Wp8PivotStrip` 等）
- 4 處硬編碼 `FontFamily.SansSerif`，繞過內嵌 Noto 字型（MIUI 上會變重回系統字體）
- 設定頁版本字串硬編碼「4.0.0」；`User-Agent` 仍寫 `SenyouTravel/3.0`、`/4.0`
- `ui/DuoAlarmScreen.kt`（iPhone 復刻）已無任何入口，成為死碼
- 首頁磁貼首次啟動全為「—」，無載入骨架；搜尋面板 AI 與手動搜尋視覺權重相同
- K75P 站名固定 9.5dp 字級，窄螢幕可能裁切

## 4. 改進路線

**第一梯（把壞的修成對的）**
1. 鬧鐘健壯化：開機／改時區重排 + 精確鬧鐘權限引導 + 震動 + full-screen intent 備援
2. 到站提醒改由精確鬧鐘驅動（30 分鐘 worker 僅負責快取與小工具）
3. 修好巴士站：獨立語意（空白 route 取該站最早班次）、顯示名稱回退 `stopName`、詳情頁列出該站路線
4. 讓安全模式／減少動畫真正生效
5. 清除剩餘彩色 emoji，統一走單色圖標

**第二梯（補回退步）**

6. 搜尋：通宵線、簡繁互轉、港鐵線名、結果分組標題
7. 收藏：公司分組 → 換站 → 釘選／排序 → 匯出
8. 港鐵站：補回輕鐵／港鐵巴士接駁
9. 路線圖：上下行倒數 + 首尾班

**第三梯（工程衛生）**

10. 測試補盲區：`AlarmRepo`／`StandbyAudio`／`NowPlaying`／`Hko`／`Api` 解析／`RefreshWorker`／`CrashLog.write`；`@Config(sdk=[34])` 擴至 26（CrashLog 的 bug 就在那裡）
11. 移除死碼：`DuoAlarmScreen`、`Tts`（初始化但不釋放）、`Settings.glass/night/big/deep`、空 `onClick` 的搜尋鍵、`Panes.kt.bak`
12. 版本字串與 `User-Agent` 統一由建置產物產生
